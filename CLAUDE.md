# Cutout

A lightweight raster scratchpad for designers: the quick bitmap fixes that Fireworks and Sketch do well, used alongside Figma. Paste or open an image, cut out backgrounds, cut/copy pixels to layers, fill, erase, scale, align, then copy back to Figma or save PNG/JPEG. It is deliberately **not** a Photoshop: direct selection and direct movement (Fireworks/Sketch model), no project files (scratchpad).

Platforms: Windows and Mac (Electron desktop app); the web version runs in any Chromium browser. Firefox and WebKit (Safari's engine, Playwright's Windows build; never real Safari) are "lightly tested" in the guide and changelog; the website claims Chromium only. Firefox has no EyeDropper, save picker or DownloadURL drag-out, all with fallbacks; it throws on `setPointerCapture` for synthetic pointer ids, hence the try/catch, and empties the data of synthetic paste events, so paste was checked with a real clipboard. WebKit passes all but clipboard image writes and the 150% seam test, and lacks canvas `filter`, so `figma.js` refuses layer/background blur where `CAN_BLUR` is false. Linux maybe later.

**Privacy rule for this repo:** committed files contain no private details about anyone working on it: no local file paths with user names, employers or company names, machine names, emails, backup setups, account details, or personal/session history. (A contributor's public GitHub identity in commits is fine; that's theirs to show.) Personal and session context goes in `CLAUDE.local.md`, which is git-ignored and never leaves the machine. Write paths as `%USERPROFILE%\…` / `~/…`.

- `cutout/figma.js`: renders a normal Figma copy (the clipboard's fig-kiwi data: Kiwi schema + zstd message, nodes, glyph outlines, components and overrides, FigJam objects). Loaded on demand with `cutout/vendor/fzstd.js` and `cutout/vendor/kiwi.js` (MIT, license headers kept; listed in README "Third-party code"). Browsers' DecompressionStream has no zstd, hence fzstd. Format notes and the test set live outside the repo (private). Scratch layers (strokes, shadows, blends, masks) are full-size canvases, so `figma.js` recycles them (`take`/`give` pool) and draws plain solid strokes and simple shadows straight onto the canvas; keep new effects on that pattern (a big FigJam board makes each scratch canvas hundreds of MB).
- `cutout/fill.js`: Smart fill, i.e. fill from the surroundings (content-aware fill, no AI). First checks whether a smooth fill predicts a thin band around the hole; if so (flat colors, gradients, the usual screenshot case) it does a harmonic fill, which can't invent anything. If the rim is a few blocks of flat color (UI cards and gaps), a block fill: rim split into one-color runs, each pixel takes the block most of its four straight-line rim neighbours belong to (when both pairs agree, the thinner run wins, so gaps continue), then blends within its block. Otherwise patch-based completion with PatchMatch, coarse to fine (texture, patterns; many runs, e.g. bricks, go here too). Smoothing rounds only revisit pixels next to ones that changed (big holes on slightly noisy images were 10x slower before). Patch fill alone once copied a nearby message bubble's end into a flat background, hence the check. One self-contained function, `cutoutPatchFill(data, w, h, mask)`, so app.js can run it in a Web Worker built from its source text (a Blob URL works from file:// pages too); falls back to the main thread. app.js crops the selection plus a margin before filling, and drops the result if the layer changed meanwhile. app.js starts and warms up the worker at idle after launch (two tiny fills), so the first fill is fast. Speed checks: research prototype fill-bench.js.

## Architecture (app.js)

- **Platform object**: the only code touching files and the system clipboard (save dialog, clipboard read/write, file picker). When `window.cutoutNative` exists (Electron preload), `Platform.isNative` / `canReadClipboard` are `true`: clipboard reads, Save/Save as and theme go through Electron; the Paste button and Paste menu items appear. In a browser `canReadClipboard` is `false` (Edge refuses clipboard reads for local file pages even after "Allow"). Ctrl+V always works via the native paste event. Drag-out of a layer row: in Electron it's a real OS file drag (`webContents.startDrag`), and the same drag coming back into the Layers panel reorders (`nativeDragId`); in a browser it's `DownloadURL`.
- **Document**: `state.artboard` (always at 0,0) + `state.layers` (bottom → top) `{ id, name, x, y, canvas, visible, src? }`. Layer canvases are **immutable**: every pixel edit makes a new canvas (copy-on-write). `src` keeps original pixels for non-destructive scaling ("Original size"); any pixel edit clears it.
- **History**: snapshots reference canvases through shared "image records"; after an edit, replaced canvases are compacted to patches of only the changed pixels (12 MP photo: ~0.03 MB for 20 edits). 512 MB budget drops oldest steps. An eraser stroke paints into a live canvas, so compaction waits until no drag is active.
- **Selection**: pixel mask in doc coords `{ x, y, w, h, mask: Uint8Array, matte? }`. `matte` = background color picked by the wand, used by edge cleanup (defringe).
- **View**: zoom/pan in device pixels, one `<canvas>` renderer. Snapping guides, spacing handles, marching ants, brush outline are drawn there.
- **Prefs**: `localStorage` key `cutout.prefs.v1` (theme, tolerances, eraser size, paste size, locks, marquee shape…). Retired keys are deleted on load.
- `window.Cutout` exposes a small debug handle used by tests.
- **Content security policy** (meta tag in `index.html`): `default-src 'none'`; scripts and styles only from the app's own files (no inline scripts, no inline `style="…"` attributes, no `eval`/`new Function`); images from the app, `data:`, `blob:` and https (Figma's image links); `connect-src` self/https/data/blob; workers from `blob:` (Smart fill). So: the pre-paint theme script lives in `cutout/theme.js`, element styles are set through `el.style` (allowed) or classes, and `figma.js` decodes Kiwi messages with its own `kiwiDecode` (reads the schema directly) instead of kiwi.js's `compileSchema`, which uses `new Function`; only `decodeBinarySchema` is used from the vendored file. `kiwiDecode` was checked value for value against `compileSchema` on all private samples. A violation shows in the console and as a `securitypolicyviolation` event; CDP `Runtime.evaluate` is exempt from the eval rule, page code is not.
- **Hidden layers**: commands that edit the active layer's pixels go through `hiddenLayer(l)` first and refuse (toast) when it is hidden, as Fireworks and Photoshop do. Layer-level commands (move, delete, flip, reorder) still work on hidden layers.
- **Undo budget**: `historyBytes` counts full canvases in undo/redo that are no longer live, patches, and the `src` originals of scaled layers.
- **New** (`newDocument`, Ctrl+N only, by design: it's a power-user shortcut for select all + delete, and the Cutout ▾ menu is for settings, not actions; the web version can't catch Ctrl+N, so it has no New): empty layers, 800 × 600 transparent artboard, save target forgotten, one undo step (so no "unsaved changes" question).
- **Undo and the view**: snapshots carry the view (`view: { s, ox, oy, fit }`); `restore` applies it only when the step changes the artboard's size (a fitted view is re-fitted), so undoing New / Trim / Canvas size puts the artboard back where it was, and undoing ordinary edits never moves a view the user has zoomed since.
- **Esc mid-drag** (`cancelDrag`): drags that change the document push their undo step through `dragHistory()`, which remembers it in `dragStep`; cancel pops and restores that step (only if it is still on top). A wand drag just ends. Cutout's own addition: neither Fireworks nor Figma cancels a drag with Esc.
- **Drags**: while a mouse drag is in progress (`drag`, except panning) the keydown handler ignores commands (an undo mid-stroke left the drag working on replaced layers); a mouse move with no button down ends a drag whose release the window never saw. Synthetic tests must not pause mid-drag: a real mouse move over the window ends it.
- **Auto-scroll** (`autoScrollWatch` / `autoScrollFrame`): marquee, move and rubber-band drags pan the view when the pointer is within 15 CSS px of the canvas edge or past it. Inside the edge it matches Figma (measured in Figma: 0 at 15 px inside, rising to 600 px/s at the edge, the same at every zoom, no build-up over time); past the edge it keeps rising to 4x that 40 px out (the owner chose it: Figma alone felt slow on big images at 100%). Full speed close to the edge keeps the toolbar side, with little room before the screen edge, as fast as the Layers panel side, replaying the last pointer position through `onPointerMove` each frame so the drag keeps extending with the pointer still. Armed only after 4 px of movement; stops on drag end / `cancelDrag`, and per side once the artboard edge is 48 px inside the view. Not for scale, artboard resize, gap or wand drags (screen-space deltas, or distance-based). Tests: `tests/page/autoscroll-tests.js`.
- **Accessibility**: Colors (WCAG 2.2 AA): `--accent` #0073E7 is for fills with white text (4.6:1, the lightest blue that passes), the same in both themes; `--accent-line` is for blue lines, rings, checkmarks and the canvas handles (#0073E7 light, #6CB4FF dark, where #0073E7 is too dark on the panels). The website uses the same pair (`--accent` / `--link`), underlines links in running text, and keeps fine print at #6B7280 or darker. Controls are reachable with Tab and show an accent focus ring; buttons never take focus on click (global mousedown), so keyboard focus only comes from Tab. Focus origin is tracked (`lastInput`, focusin marks `.pointer-focus`, `byKeyboard()`) because Chromium's `:focus-visible` turns on at the first key press even after a click: only keyboard-focused controls take Space/Enter/arrows/Esc (`keyForControl`) and show the ring, so a clicked layer row keeps Space = pan, arrows = nudge, Esc = deselect. `renderLayers` restores focus (and its origin) to the same row after rebuilding. Menus (`showMenu`) have role menu / menuitem(radio), arrow keys / Home / End / Enter / Esc / Tab, focus the first item when opened from the keyboard (`click` with `detail === 0`), return focus on close, and set `aria-expanded` on their button; arrows also move into a menu opened with the mouse. The canvas is focusable (tabindex 0) so the Menu key / Shift+F10 fires `contextmenu`; Chromium sends it with `button: -1`, positioned at the element's center and `pointerType: "mouse"` (a real right-click has button 2; test with a real key through CDP, a synthetic event hid this once): then the menu is for the selection, else the active layer, else the artboard, centered. A click on a button (which takes no focus) blurs whatever control had keyboard focus, or Space would press that control instead of panning. A letter typed on a keyboard-focused `<select>` is type-ahead, not a tool shortcut. Control+Return (`e.ctrlKey`, not ⌘) opens the same menu anywhere (`keyboardCanvasMenu`): Macs have no Menu key, and on a Mac, Tab skips buttons unless the system's Keyboard navigation is on (documented in the guide; Option+Tab reaches them). Mac keyboard and VoiceOver behavior is untested on a real Mac. Landmarks: the top bar is the banner (with a visually hidden h1 "Cutout"), the options bar a region "Options", tools a nav, the stage `<main>`, Layers an aside, the status bar the footer; form fields need a label or `aria-label` (a `title` tooltip alone doesn't count; `tests/a11y.mjs` checks all, dialogs included). Toggle buttons carry `aria-pressed`; layer rows an `aria-label` with selected / hidden; unlabeled inputs an `aria-label`. Messages: `toast()` also writes to the visually hidden live region `#announce` (emptied first, then set 50 ms later, so repeats are read); the toast itself is `aria-hidden`. `prefers-reduced-motion`: CSS transitions off, marching ants still. All SVG icons are `aria-hidden` (set at boot; the eye icons in their markup), so buttons read only their names; menu items carry `aria-label` = the label and `aria-keyshortcuts` (the shortcut and ✓ are not read as part of the name); same-text buttons get distinct `aria-label`s (Trim / Fit artboard vs Zoom to fit, Delete selected pixels); the zoom button says `Zoom 150%. Set to 100%`. Checks with real CDP key and mouse input: research `prototype/a11y-check.mjs`; what a screen reader gets (the accessibility tree in several states): `prototype/ax-tree.mjs`.
- **Rendering**: layers are drawn at exact (unrounded) device positions so they all sample one pixel grid; rounding each layer's edges separately left a 1 px seam between a hole and the piece put back in it at 150%.
- **Mac**: `IS_MAC` (navigator platform). Shortcut labels are written Windows-style everywhere (`Ctrl+Shift+S`, `Alt+A`); `fmtKeys()` turns them into ⇧⌘S / ⌥A / "Option" on a Mac (menus, tooltips at boot, toasts), so keep writing new labels Windows-style. The keydown handler treats ⌘ as Ctrl (`ctrlKey || metaKey`) and, on a Mac with Option held, reads the letter from `e.code` (Option+A types "å"). ⌘ also turns snapping off. In Electron on a Mac, `main.js` adds a menu bar (Cutout / Edit / Window / Help: User Guide → the guide, Privacy Policy → the privacy page): Cut/Copy/Paste are system roles (page gets `cut`/`copy`/`paste` events, handled in app.js), Undo/Redo/Select All go to the page via `menu:command` (text field: `execCommand`; else the same shortcut). Windows has no menu bar. Local and pull-request Mac builds are ad-hoc signed with `hardenedRuntime: false` (hardened runtime + ad-hoc signing can block launch); release builds turn it on through `electron-builder.signed.js`; images are in Open With as an alternate app (never the default). The About window shows only name and version. Windows and the browser have the same in the Cutout ▾ menu (About Cutout → `#dlgAbout`; version via `cutoutNative.getVersion`, in a browser from `cutout/version.js`); hidden there on the Mac app.

## Feature summary

Tools: Pointer (V), Marquee (M; New/Add/Subtract; Free / Aspect ratio / Exact size), Magic wand (W; live tolerance via slider or Sketch-style drag; edge cleanup), Bucket (G), Eraser (E; [ ] size). Space/scroll pans (no Hand tool, by choice).
Layers: drag, Alt-drag duplicate, corner/side scale handles (Shift/Alt), X/Y/W/H fields with proportion lock, Original size, flip (Shift+H/V), rotate 90°, rename (double-click, F2, menu), drag a row out as a PNG file (works into Figma and Explorer/Finder).
Selection: with a pixel selection, right-click anywhere on the canvas gives the selection menu (checked in Fireworks CS6); the layer menu needs no selection. Picking another layer in the Layers panel keeps the pixel selection (Fireworks CS6 does, with the Marquee tool active); clicking another layer on the canvas with the Pointer drops it (Fireworks blocks that click while a marquee is active, and a Marquee click there only clears it). Ctrl+J / Ctrl+Shift+J copy/cut to layer, Delete, fill (menu Color / Smart; Alt+Backspace is always color, Shift+Backspace always Smart fill; the Paint bucket has its own Color / Smart setting, `bucketFill`, default Color), invert, crop artboard, **Ctrl+Arrow grows / Ctrl+Shift+Arrow shrinks the selection 1 px on one side** (any shape). Selections are clipped to the artboard (`selClip`, checked against Fireworks CS6: marquee stops at the canvas edge; a selection moved off with the arrow keys keeps its shape and comes back whole), and commands act on the part inside (`selToUse`). **Shrink to content** (`shrinkToContent`, right-click / More): background = the shade most samples are close to, sampled on the selection edge, a ring 10 px in and a 3 px ring just outside (so a tight selection still sees the paper); tolerance from how much samples near it vary. Scanner edges (wobbly, gappy, fading) are peeled off sides that are on or within 16 px of an image edge: rows/columns while mostly content, then the faint tail until coverage jumps (the object). Background is the shade most samples are within 8 levels of, tolerance from samples within 16 (looser values let a light gray frame pass as paper). Peeling past 12 px means the object starts there: keep the leading rows that look like the first (the line), give back the rest. Dust is judged against the object (pieces under 0.2% of the biggest don't count). Along such sides, thin bands hugging the edge for a long stretch (or running off the selection) are lines too: an object in the scan corner covers the edge lines, so they show only beside it. If an edge line runs along a side everywhere except where the object is, the object reaches that side (its strip there can be paper-white). A piece hugging a side where a line was found (within 24 px of it, next to or along the marked line) is part of the line, never the biggest piece (a real scan: the blob where the top and side lines meet in the scan corner, a bit deeper than hugging takes, stretched a whole-page shrink to the far edge). A hugging band that touches the object (a card corner pressed against the scanner's dark edge, or the card's own outline near the edge) took part of the object with it: in the rows/columns where it touches, the box extends as far as the band goes (not to the image edge, which added paper strips). Peeled lines do the same only where the line runs beside the object for at most 15% of its side (a scanner edge starting at a card corner, where corner and line can't be told apart); a line along the whole side stays out (the tuned scans: card pressed against the top/left lines). Specks and slivers are dropped; the selection becomes the bounds of what's left. Running it again on its own result says it already fits (`lastShrink`). With no selection it uses the whole artboard (layer menu); a whole-artboard selection also samples a ring 20 px in, since its edge can be all scanner line. Detection is shared as `findObject(sel)` (fully transparent pixels never count). **Straighten** (`straighten`, selection or layer menu): convex hull of the object outline, smallest-area rectangle (rotating calipers) gives the tilt; rotates the active layer around the object center, up to 10°, exposed corners transparent. **Trim to selection** (`trimToSelection`): artboard = selection bounds + `clipLayersToArtboard()` (shared with Trim), one undo step; it replaced Crop artboard to selection, which kept hidden pixels outside that came back on copy/drag-out (one command, named like Trim). Both trims re-fit the view (`fitView(true)`). Straighten re-fits a Shrink to content selection to the leveled object (a tilted box is bigger and left a paper strip after trimming). **Clear corners** (`clearCorners`, selection or layer menu): finds the object, measures the corner radius three ways per corner (where the outline meets each side, and 0.29 r along the diagonal) and uses the median of all readings for all four (scan outlines are faint in places); clears paper-colored, non-object pixels outside that curve in each corner, plus paper touching them up to 4 px inside (the radius is an estimate). Never inside the curve, so a paper-white card strip survives. A corner with no outline readings is skipped. A square corner is skipped too: its outline runs along one edge through at least 90% of the corner zone and along the other edge for at most 20% (a card that ran off the scan; a rounded corner of a tightly cropped card has its outline along both edges apart from the curve, and a dark speck of scanner edge in a corner reads 0 without being square). Readings of 0 don't count toward the radius; when cropped, corners on a side the object doesn't reach (more than 4 px of paper or plain card) are skipped too. Known limit: Shrink to content again on an already trimmed card can peel its outline and plain margin as if it were a scanner edge (indistinguishable by shape). Whole layer or a whole-artboard selection = already cropped to the object, so `findObject(s, { edgeLines: false })` (the object's outline is on the image edge then, not a scanner line). When cropped, the paper color is read from the area's four corner patches (`findObject(s, { paper })`), since the area is mostly card and its edge would read the card as background; a gap of up to 4 px between the object box and the area edge is treated as outside the object. On opaque paper, mostly-transparent pixels are never the object and the rest is judged by color (the soft edges of the wedges Straighten leaves). Cleared with the wand matte so edge cleanup applies. A full-span-line rule was removed: it ate the object's outline on tight selections. Tested on synthetic scans only (real ones hold personal data).
Alignment: align ×6 + distribute (Alt+A/H/D/W/V/S, Alt+Shift+H/V, Figma shortcuts), smart guides + equal-spacing snapping (Ctrl disables), spacing handles and spacing field for a selected row/column.
Artboard: options bar when nothing is selected (W/H canvas-only, background, Trim, Fit); Canvas size… and Image size… in the right-click menu.
Paste/copy: a normal Figma Ctrl+C is decoded and drawn by `figma.js` as one image at 1× (all selected layers, like Copy as PNG); image fills download from Figma's signed links (CORS allows any origin, links expire after ~2 weeks). Anything it can't draw exactly, or images it can't download, → nothing pasted, toast asks for Copy as PNG (refuse rather than paste something slightly wrong). Safety net: `KNOWN` lists every Figma field figma.js draws or knows is harmless; any other field with a value refuses the paste, so new Figma features can't slip through silently. When adding support for a feature, add its fields there. Don't add broad 'harmless' prefixes: a blanket `component` prefix once hid component properties (visibility, swaps, slots), and a `variable` prefix hid variable modes (Dark pasted as Light); only metadata prefixes (prototype, publish, export, version…) remain. Variable modes: colors are re-resolved in modes set on the copied layers; a mode set on a parent frame or the page isn't in the copy, so the default mode is used (by design). Test on real kits (e.g. a Material UI for Figma copy), not just synthetic boards. `render(html, { strict: false })` draws everything and lists what it couldn't (tests only). Figma "Copy as PNG" pastes at its own 2× size; "Copy as SVG" renders at 1×. No half-size paste setting (removed). Copy writes PNG to the clipboard.
Save: Ctrl+S (first time: format/quality dialog, then saves silently to the same file), Ctrl+Shift+S Save as. The first image added to an empty document (paste, open, drop) starts a new document: the save target is forgotten, so Ctrl+S can't silently overwrite the file the previous image went to (`addImageLayer`). Saving retries briefly if another program locks the file. Close warning only with unsaved changes.
Theme: System / Light / Dark (Cutout ▾ menu); the native title bar follows it. Math in number fields (`60/2`, `*2`, `50%`, ↑/↓).

## Design and copy conventions

- Follow **Figma conventions** (shortcuts, behaviors) unless there's a reason not to; Fireworks for bitmap-editing habits; native Mac conventions on the Mac.
- Options bar: current tool's settings first, then the selection context (artboard / layer / pixels). Spacing scale: 6 px inside a cluster, 16 px + divider between clusters, 24 px tall controls.
- UI copy: **short and plain, no em dashes**, no explanatory filler ("No image on the clipboard", "Selection is empty"). Tooltips = name + shortcut.
- Never make Cutout a default app for any file type; it only appears in "Open with".
- Declined for now: one-click AI background removal (too heavy; if revisited, use an OSI-licensed model such as U²-Net / IS-Net / MODNet), AI fill (Smart fill covers it without a model; if revisited, MI-GAN (MIT) is the small option, LaMa (Apache 2.0) the strong one), lasso, recover-after-close, uniform grow/shrink.

## Testing

**`npm test`** (`tests/run.mjs`) starts Cutout through `tests/harness.js` (throwaway settings folder, so it runs next to an open Cutout; the Save dialog answers by itself) and drives it over CDP: the page suites in `tests/page/` (made-up images only; each defines `window.<name>()` returning PASS/FAIL lines), `tests/figma.mjs` (Figma paste: `tests/figma-copy.mjs` builds normal Figma copies from scratch with a small Kiwi schema using Figma's field names, deflate or zstd; add a case there when supporting a new Figma feature) and `tests/a11y.mjs` (real key and mouse input through CDP). Exit code 1 on any failure; `node tests/run.mjs <name>` runs matching suites, `VERBOSE=1` prints every check. `.github/workflows/tests.yml` runs it on every push to main and every pull request (Linux, in xvfb; stores no build files). Add a check there with every fix. Tests that need the private Figma samples stay outside the repo.

**Mac App Store sandbox check** (`.github/workflows/mas-sandbox.yml`, GitHub's Mac runner; runs when main.js, preload.js, the package files, `installer/entitlements.mas*.plist` or `tests/mas/` change, on `v*` tags and by hand): builds Electron's Mac App Store version (`mas-dev`, `tests/mas/build-config.js`), signs it ad-hoc with the store's sandbox entitlements plus a stand-in app group and, for the check only, `network.server` for the DevTools port (`tests/mas/sign-adhoc.sh`), then `tests/mas/sandbox-check.mjs` launches it through LaunchServices (`open`) and checks: files from Finder (at launch and while running), the real Save panel (driven with System Events keystrokes; the panel hides extensions, so names are typed without one), saving again, JPEG, the clipboard, https and settings across a relaunch. The sandbox grants the Save panel's file, not its folder, so in the store build (`process.mas`) `file:write` writes the file directly instead of temp file + rename, and the Save panel remembers the last folder itself. Not covered: drag-out, drops onto the window, the color picker, the look. For those, run the workflow by hand: it keeps the sandboxed app as a one-day download (`cutout-sandboxed-test`), ad-hoc signed, so it opens on any Mac (Open Anyway once) without TestFlight or an Apple account; delete it after testing (it shares the app ID with the installed Cutout).

The built-in browser pane can't load `file://` pages with relative CSS/JS, so serve the folder with a tiny local server and test at `http://localhost:8765/`:

```powershell
# serve.ps1 (keep in the session scratchpad; run in the background)
param([string]$Root, [int]$Port = 8765)
$listener = [System.Net.HttpListener]::new(); $listener.Prefixes.Add("http://localhost:$Port/"); $listener.Start()
while ($listener.IsListening) { $ctx = $listener.GetContext(); $path = [Uri]::UnescapeDataString($ctx.Request.Url.AbsolutePath.TrimStart('/')); if ($path -eq '') { $path = 'index.html' }
  $file = [IO.Path]::GetFullPath((Join-Path $Root $path)); if ($file.StartsWith($Root) -and (Test-Path $file -PathType Leaf)) { $b = [IO.File]::ReadAllBytes($file); $ctx.Response.Headers.Add('Cache-Control','no-store'); $ctx.Response.OutputStream.Write($b,0,$b.Length) } else { $ctx.Response.StatusCode = 404 }; $ctx.Response.Close() }
```

Pane quirks: when hidden, `requestAnimationFrame` doesn't run and screenshots fail; dispatch `window.dispatchEvent(new Event('resize'))` after load so the canvas size / devicePixelRatio are synced before simulating pointer events; undo replaces layer objects (re-fetch them after undo); synthetic keys can't trigger a real system paste. Test real behavior by dispatching PointerEvent/KeyboardEvent and paste events with mocked `clipboardData`.

Electron: launch with `--remote-debugging-port=<port>` (source: `node_modules\electron\dist\electron.exe . --remote-debugging-port=9333 file.png`; installed: `Cutout.exe --remote-debugging-port=…`) and drive the page with `Runtime.evaluate` over the CDP WebSocket (Node has `fetch` + `WebSocket`). Put a real image on the clipboard with `System.Windows.Forms.Clipboard.SetImage` to test native paste. To test Save without a real dialog, run a small wrapper main that replaces `dialog.showSaveDialog` and sets a separate `userData`, then `require`s `main.js`. Don't fire a synthetic `dragstart` on a layer row in Electron: it starts a real OS drag that blocks the main process until killed. Mac code paths can be tested on Windows: CDP `Emulation.setUserAgentOverride` with platform `MacIntel`, then reload (with no unsaved layers, or the unsaved-changes dialog blocks). Electron 45 clipboard is W3C-style (`clipboard.read()` → items with `getType(mime)`); `readImage`/`readHTML` no longer exist.

Windows "Open with": Windows 11 lists a per-user desktop app only with the full Default Apps registration (`installer/installer.nsh`: RegisteredApplications → Capabilities → FileAssociations, plus OpenWithProgids). A running Explorer caches the menu: after (re)installing, restart Explorer before judging. To check without clicking, build the classic context menu for a file in a fresh process (`SHParseDisplayName` → `IShellFolder.GetUIObjectOf` → `IContextMenu.QueryContextMenu`, then `IContextMenu3.HandleMenuMsg2(WM_INITMENUPOPUP)` on the "Open with" submenu) and read the item names. `OpenWith.exe <file>` opens the set-default dialog instead, so don't use it.

**Registry writes from the Claude desktop app don't reach Windows.** It is a packaged (MSIX) app, so every process it starts (shell, installers) writes HKCU registry keys into its private hive (`%LOCALAPPDATA%\Packages\Claude_*\SystemAppData\Helium\UserClasses.dat`). Those processes read them back fine, but Explorer never sees them; files land on the real disk. So a first install, or any installer change to the registration, must be run from Explorer, and registry checks from that shell prove nothing about what Explorer sees.

## Decision: native app with Electron

Chosen over Tauri. Reasons: identical Chromium engine on Windows/Mac/Linux, so everything Cutout already uses (EyeDropper, ClipboardItem PNG, drag-out, save picker) works unchanged on Mac; roughly half the build effort; least risk. Accepted cost: ~90 MB download / ~250 MB installed, ~70–100 MB more RAM than Tauri. The Platform layer keeps a later switch to Tauri contained if size ever matters.

## Distribution options

1. **GitHub Releases**: built installers attached to tagged releases. A private repo's releases are private too; public downloads need a public repo (publish with fresh history) or a separate public releases repo.
2. **winget** (free): a manifest in `microsoft/winget-pkgs` pointing at the GitHub Release installer (NSIS `/S` silent install works); `wingetcreate` or a GitHub Action (e.g. winget-releaser) automates updates. Unsigned is accepted; users may see SmartScreen.
3. **Mac outside the store**: done from 2.0.0 (Apple Developer Program, $99/yr; Developer ID signing + notarization in CI). Homebrew cask possible next.
4. **Stores**: Microsoft Store via MSIX (set up, see Microsoft Store above). Mac App Store via the `mas` target: App Sandbox (user-selected file access, Open with, drag-out all fit Cutout) and per-version review.

**Code signing**: in use from 2.0.0 (Windows: Azure Artifact Signing as an individual; Mac: Developer ID, see Releases). The Windows `publisherName` must never change once released, or automatic updates stop installing. The options that were compared, for Windows: Microsoft Store (free), Azure Artifact (Trusted) Signing (~$10/month, individuals only in some countries), classic OV certificate (~$200–400/yr), SignPath Foundation (free for OSI-licensed open source; certificate issued to the foundation). Mac: effectively required for others; the Apple Developer Program includes the certificate and notarization (in use, see Releases).
